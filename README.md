# 文冬三天两夜 · 家庭游行程

2026 年 8 月 29–31 日（周六至周一国庆日）文冬（Bentong, Pahang）家庭旅游行程网页。
一家七口（4 大人 + 3 小孩），住 27 Ah Peng — Bentong At Your Doorstep。

## 内容

- **住宿资讯** — Agoda 订单资料、地图导航、一键致电
- **三日行程** — 时间轴排程，含车程、门票、营业时间
- **备选方案** — 下雨或瀑布关闭时的替代玩法
- **美食与手信** — 老街必吃、文冬姜、豆腐卜、应季榴莲
- **实用资讯** — 开车过路费、天气穿着、现金网络、带小孩安全、紧急联络
- **家庭投票** — 一人一票，即时汇总全家排名，还能自己加景点/美食
- **行程自动跟票走** — 票多的站标名次，没人投的标「可以换掉」，顺路的高票项目列成建议
- **打包清单** — 可勾选，进度存在浏览器 localStorage
- **预算估算** — 7 人不含住宿的花费区间

## 使用

已上线：<https://q44travel.web.app>

也可以直接用浏览器打开 `index.html`，不必架伺服器。
页面分成 **住宿 / 三日行程 / 景点 / 吃什么 / 家庭投票 / 备忘** 六个分页，
手机、平板、桌面都做了响应式排版，并支援浅色 / 深色主题。

## 投票身分怎么算

第一次打开页面会问「你是谁」，七个名字（爷爷、嫲嫲、爸爸、妈妈、霆轩、霆言、霆正）点一个。
选好之后，这个名字就**绑在这台装置上**：

- 身分存在 localStorage（不是 session，关掉浏览器也还在）
- 每笔投票都带一个 `device` 值，资料库规则规定**只有原本那台装置改得动**
- 别人用别的手机点同一个名字，会被挡下来，也删不掉你的票
- 投完随时能改主意，再点一次就取消，票数即时更新
- 点错名字：页面最下面可以清掉本机身分，但那个名字要到 Firebase 后台删掉该笔纪录才放得出来

## 行程怎么排出来的

三天的行程不是写死的，是每次开页面照票即时生成的：

- 每天是一排**时段**（D2 是 08:00 / 09:30 / 12:30 / 15:30 / 17:30 / 19:00），
  票最高又符合资格的项目坐进那个格子
- 每一项都带排程资料：在哪一区、要多久、能排哪些时段
  （瀑布只排上午因为 16:30 关、夜市只排周六晚、要预约的会标出来）
- 出发、打电话、入住、退房、回程是固定的 —— 那不是喜好
- 有票但塞不下的，列在行程页顶端

### 爸爸可以自己排第几天、几点

第一个用「爸爸」这个名字的装置会自动认领**排行程权**，行程页多一个「调整行程」钮（只有他看得到）：

- 每一站可以选换到哪一天、哪个时段，按「放这里」就钉住
- 钉住的站票再高也挤不掉；「取消固定」放回去照票排
- 钉到不合适的时段（例如瀑布排下午）会标红并附警告，但还是照他排的
- 资料库规则只认那台装置，别人写不进 `plan`，也删不掉

## 家庭投票的两种模式

页面会自己判断该用哪一种，「家庭投票」版块最上面的状态列会显示目前模式。

| 模式 | 条件 | 怎么运作 |
| --- | --- | --- |
| **即时同步** | 已填好 `firebase-config.js` | 一人投票，所有开着页面的人立刻更新 |
| **代码汇总** | 没填设定，或环境挡掉外部请求 | 各自投完产生 `BT26.xxx` 代码，丢家族群，一人贴上汇总 |

要开启即时同步，照 [SETUP.md](SETUP.md) 走一遍（约 10 分钟，全在浏览器里做）。
